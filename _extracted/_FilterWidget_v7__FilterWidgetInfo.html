Getting Started

FilterWidget v7 is a zero-config dashboard controller for LogicMonitor. It drives cascading filter dropdowns that update your entire dashboard via LM's native URL-based resource property filters. All devices are fetched into a local cache at startup, and filter options are extracted client-side for instant cascading.

Two-Phase Initialization
Filter values and the blue status strip restore instantly from URL parameters or localStorage. The device cache loads in the background (a few seconds) to refresh dropdown options. You can use your restored filters immediately without waiting.

No Dashboard Tokens Required
FilterWidget v7 is zero-config. It uses LogicMonitor's native URL-based resource property filter mechanism — no dashboard tokens needed. Hidden filters add values to the URL automatically without any visible dropdown.

Using Filters

Multi-Select Dropdowns

Filter dropdowns support multi-select by default. You can select one or more values per filter, and all selected values are included in the dashboard URL. Individual filters can be configured as single-select in the wizard.

  1. Click on a filter input to open the searchable dropdown. A ✓ checkmark appears next to each selected option.
  2. Type to search — the list filters in real-time as you type. The dropdown stays open so you can select multiple items.
  3. Click options to toggle them on or off. The dropdown does not close after each click.
  4. Selected values appear as tag chips below the input. Each tag has an × button to remove it individually.
  5. When multiple values are selected, the input field shows "N selected" (e.g., "3 selected").
  6. Click outside the dropdown to close it, then click Apply to filter the dashboard.
About "All" Option
Selecting "All" clears any other selected values for that filter (they are mutually exclusive). Similarly, selecting a specific value removes "All" from the selection. In the URL, "All" means no filtering for that property.

Action Buttons

How Cascading Works

Filters extract values client-side from a shared device cache. When you select or deselect a value:

  • The widget narrows the device pool using OR logic across all selected values — a device matches if it matches any selected value
  • All downstream filters recalculate their options from the narrowed pool
  • Previously selected downstream values that are no longer valid are automatically pruned
  • Valid downstream selections are preserved
  • Hidden filters are included in the cascade but do not show a dropdown; they auto-select their values silently
No Options?
If a filter shows no options, the combined selections in upstream filters may have narrowed the device pool to zero matching devices. Try deselecting some values or selecting "All" in an upstream filter to widen the pool.

Hidden Filters New in v7

A hidden filter has hidden: true set in its configuration. It participates fully in the dashboard URL and the cascading logic, but it never renders a dropdown in the filter bar and never appears in the blue status strip.

What Hidden Filters Do

  • Their selected values are always included in the URL built by Apply — silently restricting the dashboard
  • They auto-select all available options (excluding "All") after their data loads
  • If preselectedValues is configured, only those specific values are auto-selected instead of all
  • They still respect visibleWhen — a hidden filter only activates when its upstream condition is met
  • Works with both source: "api" (device property extraction) and source: "static" (custom list)

Common Use Cases

Use CaseHow
Always exclude a resource typeHidden filter on system.azure.tag.aztype with preselectedValues: ["VM"] and filterMode: "exclude" — silently hides all VMs
Restrict to a subtreeHidden filter on system.groups that auto-selects all groups under a given path, narrowing the dashboard without exposing the filter
Single-value silent filterHidden filter with preselectedValues: ["Production"] that always passes environment=Production into the URL

How to Configure a Hidden Filter

  1. Open the wizard via ▶ Filter Configuration → Edit Configuration
  2. Navigate to the filter's step and go to the Display Options section
  3. Toggle "Hide from filter bar" to on
  4. Optionally set Preselected Values to restrict which values are auto-selected
  5. On the Review step, hidden filters show an orange (hidden) badge and appear dimmed in the preview mockup
  6. Save the configuration — the hidden filter will take effect immediately
Hidden vs. Visible in the Code
Internally, getVisibleFilters() includes hidden filters (for URL building and cascade), while getDisplayedFilters() excludes them (for rendering the filter bar and the blue status strip). Hidden filters are always "active" but never shown.
Dashboard Appears Empty?
If the dashboard shows no resources after clicking Apply, a hidden filter with no matching values may be over-restricting. Check your hidden filter configuration and ensure the preselectedValues or auto-selected values actually match devices in your environment.

Exclude Mode New in v7

By default, filters use include mode — the dashboard shows only resources that match the selected values. With exclude mode, the dashboard hides resources that match the selected values, showing everything else.

How Exclude Mode Works

When filterMode: "exclude" is set on a filter:

  • The URL filter entry gets "i": "e" added, which is LogicMonitor's native exclude flag
  • The value entries omit isSelected, matching LM's native exclude format
  • The filter label shows a Exclude badge
  • The blue status strip prefixes the filter name with "Exclude"
  • The wizard review step shows the filter with a red "Mode: Exclude" indicator

Use Cases

ScenarioConfig
Hide specific resource typesHidden filter + exclude mode → silently removes matching resources from all dashboard widgets
Remove maintenance hostsVisible filter on a maintenance property, exclude mode lets users pick which hosts to suppress
Exclude a department from viewHidden exclude filter on customer.squad to prevent a specific squad from appearing in shared dashboards

Configuring Exclude Mode

  1. Open the wizard and navigate to the filter's Display Options section
  2. Toggle "Exclude Selections" to on
  3. The Review step will show a red "Mode: Exclude" indicator for that filter
  4. Save the configuration
URL Format Difference
Include mode: {"n":"prop","v":[{"value":"X","label":"X","isSelected":true}],"t":"RP"}

Exclude mode: {"n":"prop","v":[{"value":"X","label":"X"}],"t":"RP","i":"e"}

Preselected Values New in v7

The preselectedValues property on a filter defines an array of values to auto-select. Its behavior differs depending on whether the filter is hidden or visible.

For Hidden Filters

  • Without preselectedValues: the hidden filter auto-selects all available values (excluding "All")
  • With preselectedValues: ["val1", "val2"]: the hidden filter auto-selects only those specific values, restricting the URL filter to them

For Visible Filters

  • When no URL state or localStorage state exists for the filter, the widget auto-selects the preselected values as the default selection on first load
  • Once the user changes the selection and clicks Apply, that user selection takes over and the preset defaults no longer override
  • On Reset, the filter clears completely (preselected defaults are not re-applied — only on true first load with no existing state)

Configuring Preselected Values

  1. Open the wizard and navigate to the filter's Display Options section
  2. Find the Preselected values picker — it shows checkboxes for all available values loaded from the device cache (API source) or the static options list
  3. Check the values you want preselected, or use Select All / Clear All buttons
  4. Save the configuration
Backward Compatible
Filters without preselectedValues behave exactly as before. For hidden filters, omitting it means all values are auto-selected (the original v7 hidden filter behavior). For visible filters, omitting it means no default is applied.

URL-Based Dashboard Filtering

When you click Apply, FilterWidget v7 constructs a URL with a filters query parameter containing your selections as LM resource property filters. Both visible and hidden filters contribute to this URL.

How It Works

  1. Each filter's selected values (including auto-selected hidden filter values) are encoded as resource property filter entries in the URL
  2. Filters with "All" selected produce an empty v array (no filtering for that property)
  3. Exclude-mode filters add "i":"e" to their URL entry
  4. The page reloads with the filter URL and all dashboard widgets display matching resources
  5. Anyone opening the same URL sees the same filtered view — URLs are shareable

URL Match Patterns (Glob Patterns)

Each filter can use a glob pattern to control how values are matched in the URL filter. The ${value} placeholder is replaced with the user's selection.

Prefix Match (default)
${value}*
Matches resources where the property starts with the selected value. Default if no pattern is specified.
Exact Match
${value}
Matches only resources where the property equals the selected value exactly.
Contains Match
*${value}*
Matches resources where the property contains the selected value anywhere.
system.groups Handling
For filters using system.groups, values are automatically reconstructed into full group paths (e.g., Customers_Azure/SQUAD_NA2/Baptist Health*) based on the filter's glob pattern configuration.

Filter State Priority

When the widget loads, it restores filter state using this priority order:

PrioritySourceDescription
1URL parametersFilters parsed from the current page URL. Highest priority — allows shareable links. Hidden filters read their values from the URL on load.
2localStorageLast-used filter selections saved in your browser.
3Preselected defaultsAuto-selected values from preselectedValues config. Applied only when no URL or localStorage state exists.
4EmptyNo filters selected; visible dropdowns start empty.

Wizard Configuration

FilterWidget v7 uses a step-by-step wizard for configuring filters. No raw JSON editing required. Access it via the "▶ Filter Configuration" menu in the top-right corner and selecting Edit Configuration. Supports up to 15 filters.

Config Button Disabled?
The configuration button is disabled until the device cache finishes loading (a few seconds). A centered "Loading device data..." banner is shown while the cache loads. Wait for it to disappear before opening the wizard.

Step 1: Setup

Choose how many filter dropdowns you want (1–15). Each filter extracts unique values from a device property. Selecting a value in one filter narrows the devices available to subsequent filters. Filters can be conditionally visible and can be hidden from the filter bar entirely.

15 Filter Maximum
v7 supports up to 15 filters (increased from 10 in v4/v5/v6). The maximum is controlled by the MAX_FILTERS constant in the widget script.
Steps 2–N: Configure Each Filter

Each filter step has the following sections:

Name Your Filter

  • Filter Label — Display name shown above the dropdown
  • Search Hint — Placeholder text in the input (e.g., "Search Squad...")
  • Internal ID — Auto-generated from the label, but manually editable. Manual edits are preserved through label/visibility changes.

Visibility (filters at position 2+)

  • Toggle "Only show when an upstream filter matches specific values" to make the filter conditionally visible
  • Select the upstream filter and the values that trigger visibility
  • If the upstream filter uses a custom list, checkboxes appear; if it uses API source, type values manually

Data Source

  • LogicMonitor API — Extracts unique values from a device property across all cached devices
  • Custom List — A static list of options you define (e.g., "Azure Filter", "QTS Filter")

Display Options v7

  • LM Filter Property Name — The device property matched in the dashboard URL
  • Device Property to Extract From — Property scanned across cached devices (API source only)
  • Value Extraction Preset — "Use as-is" or "Split by character and pick a piece"
  • Include "All" Option — Whether to show an "All" at the top
  • Allow Multiple Selections — Toggle multi-select per filter
  • URL Match Pattern — Glob pattern for URL matching (e.g., ${value}*)
  • Hide from filter bar (hidden) — Makes this filter invisible in the UI but active in the URL
  • Exclude Selections Exclude — Switches from include to exclude mode for this filter
  • Preselected values — Values to auto-select on load (hidden filters) or as defaults (visible filters)
Live Preview
A live preview panel shows the actual values extracted from the cached device data, so you can verify extraction settings before saving.
Final Step: Review & Save

The review page shows summary cards for each filter, plus a preview mockup of the filter bar.

  • Use up/down arrows on each card to reorder filters; use Remove on a card to delete that filter (at least one filter must remain)
  • Hidden filters show an orange (hidden) badge and appear dimmed in the mockup
  • Exclude-mode filters show a red "Mode: Exclude" indicator
  • Verify each filter's property, extraction method, and options
  • Click Save Configuration to apply and auto-write the config back to the widget source
After Saving
The wizard closes and the widget reloads with your new configuration. The config is also written into the widget's HTML source via the LM API, so all users on this dashboard get the updated config on next load.
Popup Blocked?
The wizard opens in a popup window. If your browser blocks it, a fallback inline modal will appear. To use the popup, allow popups for the LogicMonitor domain.

Self-Updating Configuration

Every time you save the configuration, FilterWidget v7 writes the new config directly back into its own widget source HTML via the LM REST API. This means all users who load the dashboard will automatically see the updated configuration — no need to manually import a JSON file or edit the widget HTML.

How It Works

1
Locate Self
Scans text widgets for sentinel marker
2
Fetch Content
GET full widget object from LM API
3
Splice Config
Replace config between sentinel markers
4
Write Back
PUT updated widget to LM API

Config Sentinel Markers

The DEFAULT_FILTER_CONFIG block in the widget source is wrapped with two sentinel comments:

// %%FWV7_CONFIG_BEGIN%% const DEFAULT_FILTER_CONFIG = { /* ... your config ... */ }; // %%FWV7_CONFIG_END%%

These markers serve two purposes: they identify the widget's own text widget in the LM API (fingerprint), and they act as splice anchors for safely updating only the config block without touching any other HTML, CSS, or JS in the widget.

Graceful Fallback

  • If the API PUT fails (insufficient write permissions, popup context, network error), the config is still saved to localStorage and the user sees a warning message
  • The filter still works correctly using localStorage config
  • Other users will not see the updated config until someone with write permission saves again
Requires Write Permission
The self-update requires write access to the LogicMonitor dashboard. Read-only users can still configure filters locally (saved in localStorage) but the changes won't persist for other users.

Export / Import as Backup

Even with self-updating config, JSON export/import is still available via the settings menu as a backup and cross-environment transfer mechanism.

Troubleshooting

Wizard popup doesn't open
Your browser may be blocking popups. Allow popups for the LogicMonitor domain, or use the fallback inline modal that appears automatically. Check for a browser notification about blocked popups in the address bar.
Config button is grayed out / disabled
The configuration button is disabled until the device cache finishes loading. A centered "Loading device data..." banner is shown while loading. Wait for it to disappear. If the button stays disabled, check the browser console for errors and verify your LM session is active.
Widget or filters take a long time to load
Load time grows with how much work the widget does: fetching and scanning the device cache, then building options for each API-based filter in order. If startup feels slow, review your configuration and remove unnecessary filters (filters you don't need for that dashboard). More filters mean more extraction passes and more cascading work. Prefer conditional visibility (visibleWhen) so inactive branches don't add cost, use hidden filters only where needed, and avoid duplicating logic across filters. After trimming, use Clear API Cache and refresh once to measure improvement.
"Authentication failed" error
Your LogicMonitor session has expired. Refresh the page and log in again. The widget reuses your active LM session cookies for all API access.
Dashboard appears empty after clicking Apply
One of the following may be over-restricting:
  1. A hidden filter with no matching values. Check hidden filter config — its preselectedValues or auto-selected values may not match any devices.
  2. A filter in exclude mode that is excluding too much. Check exclude-mode filters and their selections.
  3. Upstream filters that have narrowed the device pool too aggressively (combination of multiple strict selections).
Hidden filter doesn't seem to be doing anything
Check the following:
  1. Verify hidden: true is set on the filter in the config (wizard Review step will show the orange "(hidden)" badge)
  2. Open browser DevTools → Network tab and click Apply. Inspect the URL — the hidden filter's property should appear in the filters parameter
  3. If preselectedValues is set, confirm those values actually exist in the device data (open the wizard and check the live preview)
  4. If the hidden filter has visibleWhen, make sure its upstream condition is currently met
Self-update fails / "Saving to widget source" warning appears
The self-update writes back to the widget via the LM REST API and requires write permission on the dashboard. If you see a warning instead of a success message:
  1. Confirm you have write/edit access to the dashboard
  2. If the widget is running in a popup or iframe context, the PUT may be blocked. Use Export Config as a manual backup instead.
  3. Config is still saved to localStorage, so the widget works for you. Other users won't see the updated config until someone with write access saves again.
Filters show no options or wrong values
  1. Check that valuePropertyName matches an actual device property name
  2. Open the wizard and check the live preview panel — it shows extracted values from cached devices
  3. For "Split and pick" extraction, verify the separator, starts-with filter, split character, and piece index
  4. Check the browser console for messages about device match counts
Filter options seem outdated / stale data
Use Clear API Cache from the settings menu (▶ Filter Configuration → Clear API Cache). The device cache has a 30-minute TTL. After clearing, refresh the page for fresh data.
Preselected values not auto-selecting on first load
Preselected defaults for visible filters only apply when there is no existing URL state or localStorage state for that filter. If you've previously applied filters, localStorage has saved values that take priority. Clear All from the Presets panel and refresh to test first-load behavior.
Exclude mode filter is still showing excluded resources
Verify the URL after clicking Apply contains "i":"e" in the filter entry for that property. If not, re-open the wizard, check that "Exclude Selections" is toggled on for that filter, and save again. Also confirm the LM dashboard version supports the i exclude flag (it's a native LM feature available in current versions).
Conditional filter not appearing
Check the visibleWhen rule in the wizard. The upstream filter's selected display name must exactly match one of the allowed values. For multi-select, the conditional filter appears if any of the upstream selections match.
Wizard popup shows a blank page
Check the browser console (F12) for JavaScript errors. The most common cause is a template literal escaping issue. Try refreshing the page and reopening the wizard. If it persists, use Export Config to backup, click Clear All, and re-import.
How do I reset to the default configuration in the widget script?
Use Filter Configuration → Reset to embedded default…. You can download a JSON backup of your current config first, then confirm. This replaces the browser's saved configuration with the default definitions pasted into the text widget in LogicMonitor. Your named Filter Presetsare not deleted.

Clear All (under Filter Presets) is different: it wipes presets, cached config, wizard state, selections, and API cache in one step. Use that only when you want a full local wipe; afterward, reload the page to pick up the embedded default from the script.

I updated the config but other users still see the old config
The self-update may have failed silently (check for a warning message after saving). Ensure you have write access to the dashboard. If the PUT succeeded, other users should see the new config on their next page load — they may need to clear their localStorage cache (Clear All) if they have an older config cached locally.
Getting Help
If you continue experiencing issues, export your configuration (Filter Configuration → Export Config) and share it with your administrator for debugging. Include any browser console errors (F12 → Console tab).
